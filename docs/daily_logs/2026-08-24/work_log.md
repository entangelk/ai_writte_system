### 구현 판단 (기록)

- **화면 프리필은 상세 응답으로만** — 목록 기준 프리필은 다른 관리자의 변경 뒤 낡은 값으로
  입력을 시작하게 하고 상세 도착과 함께 사용자 입력을 덮어쓴다. 폼은 상세 도착 전 입력 불가.
- **소수(7.5)는 클라이언트에서 막지 않는다** — B1(StrictInt 422)이 서버 계약이고, 타입 규칙을
  프론트에 복제하면 정합 지점이 둘이 된다. 빈 칸·NaN만 프리필 단계에서 걸러진다(그 둘은
  "0 한도"/"무제한"이라는 **다른 요청**이 나가는 사고라 도메인이 아니라 직렬화 방어다).
- **연결 가드(backend→프론트 라벨)를 추가하지 않았다** — 활동 로그의 `test_activity_ui_labels`
  패턴은 불투명 string literal(작업 id)과 프론트 라벨 표라는 **둘의 정본**이 있어서다. quota는
  payload가 생성된 schema.d.ts로 타입 결합돼 있고 UI가 분기하는 런타임 리터럴은
  `status === "suspended"` 하나(`describeRemaining`도 가드 없이 같은 값을 이미 소비한다).
  pytest가 TSX 산문을 grep하는 것은 새 가드 패턴 발명이며 계약을 하나도 보호하지 않는다.
