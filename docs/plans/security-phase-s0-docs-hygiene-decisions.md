## Decision needed

**공개 저장소에 남은 실제 사설 주소(2대의 llama.cpp 호스트 + 배포 호스트 LAN IP)와 평문 비밀번호를, *어느 파일 계열까지* 고쳐 쓰는가.**

선례에서 유도되지 않는 이유가 **셋**이다.

1. **저장소 안에 충돌하는 두 규칙이 있다.**
   - [`HANDOFF.md:4`](../../HANDOFF.md) — *"원격 배포 대상의 IP·호스트명…을 `HANDOFF.md`·`docs/daily_logs/`·`docs/verifications/`·`CHANGELOG.md` 등 저장소 문서에 기록하지 않는다."* → **이력 계열을 명시적으로 지목한다.**
   - [`HANDOFF.md`](../../HANDOFF.md) 표준 제약(제품명 D5) — *"★ 이력 문서는 대상이 아니다 — `HANDOFF.md`·`CHANGELOG.md`·`docs/` 에 옛 이름이 남는 것은 맞다(그것이 그때의 사실이다)."* → **같은 파일 계열을 명시적으로 면제한다.**

   두 규칙은 서로 다른 축(보안 / 표시명)에 대한 것이지만 **대상 파일 목록이 같다.** 어느 쪽이 이 축에서 canonical 인지는 오너만 정할 수 있다.

2. **히트의 87%가 독립 검증 기록과 작업 로그다** — 그중에는 **이 발견을 만든 감사 기록 자신**도 있다. 감사 기록을 고쳐 쓰면 *발견의 근거가 발견 문서에서 사라진다.*

3. **재유입 방지 가드의 폭이 곧 앞으로의 마찰**이다. [`../../tests/test_signup_throttle.py`](../../tests/test_signup_throttle.py) 의 XFF 신뢰 셀은 **일부러 사설 대역 호스트 주소를 픽스처로 쓰고**, 계약 literal 에도 사설 CIDR 이 있다 — 광의 정규식을 전건에 걸면 **정상 코드를 문다.**

## D1 — 스윕 범위: 어느 파일 계열까지 고쳐 쓰는가 → **D 채택**

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **A. 살아 있는 것만** | `docs/plans/` · `system-contract-sot.md` · `scripts/` 만 고친다. `CHANGELOG.md`·이력 계열은 그대로 | 이력 보존 원칙과 충돌 0. 변경 10파일 미만이라 리뷰가 싸다 | **134히트 중 18만 걷힌다.** 보안 규칙이 명시적으로 지목한 `daily_logs`·`verifications`·`CHANGELOG` 가 통째로 남아 규칙 위반 상태가 지속된다 |
| **B. 현행 주소만 전 계열** | 지금 쓰는 베타 LLM 호스트 + 배포 호스트 LAN IP 만 **모든 파일**에서 걷고, 이미 안 쓰는 구 검증 머신 주소는 이력에 둔다 | **살아 있는 표적만 없앤다** — 위험 감소분의 대부분을 얻으면서 이력 편집을 절반으로 줄인다. 감사가 매긴 심각도(LOW)와 비용이 맞는다 | 규칙 문언은 "쓰는 주소"가 아니라 "IP·토폴로지"를 금지한다 — 문언 위반은 남는다. 남은 한 주소가 **"어느 대역이 이 집 LAN인가"를 그대로 드러낸다** |
| **C. 전 계열 전건** (감사 기록 포함) | 3개 주소 + 평문 비밀번호를 **56파일 전건** 역할 별칭으로 치환 | 규칙과 저장소 상태가 처음으로 일치한다. 가드를 예외 없이 걸 수 있다(D3 가 단순해진다) | **이력 문서 46개를 사후 편집한다** — "그때의 사실" 원칙을 이 축에서 깬다. **감사 기록이 자기 발견의 근거를 잃는다.** 벤치마크 JSON 의 `base_url` 은 측정 아티팩트라 수정이 곧 데이터 변조로 읽힐 수 있다 |
| **★ D. 전 계열 전건 + 감사 기록 예외** | C 와 같되 [`security_audit_dual_workflow.md`](../verifications/2026-09-05/security_audit_dual_workflow.md) 한 파일만 원문 보존(발견의 근거이므로) | 이력 편집의 이득을 다 얻으면서 **발견 문서의 증거력을 지킨다** | 예외가 하나 생기므로 D3 가드에 허용목록이 반드시 필요하다. "감사 기록만 왜 예외냐"를 다음 사람이 매번 다시 묻는다(주석으로 잠가야 한다) |

**추천(채택): D.** 이유는 셋이다. ① 두 규칙의 충돌은 **보안 규칙이 더 최근이고 더 구체적**이다(2026-08-28 추가, 파일 계열을 열거) — 제품명 면제는 *표시명* 축의 판단이지 비밀값 축의 판단이 아니다. ② 이 저장소는 이미 **역할 별칭**을 배포 기록의 표준 표기로 쓰고 있어(S-6·S-7 행 전체가 그 형식) 이력 편집이 *사실을 지우는 것이 아니라 표기를 규칙에 맞추는 것*이 된다 — 어느 머신이 무엇을 했는지는 별칭으로 그대로 읽힌다. ③ 감사 기록만 예외로 두는 비용은 **가드 허용목록 한 줄**인데, 그것을 안 두면 *발견을 서술한 문서가 발견을 재현할 수 없게* 된다.

**시행**: 벤치마크 JSON 2건은 스키마를 유지한 채 값만 별칭으로 바꿨다(`"base_url": "http://<베타-LLM>:9080"`) — 키를 지우면 그때 무엇에 붙어 측정했는지가 사라진다.

## D2 — 치환 리터럴: 무엇으로 바꾸는가 → **A(산문) + D(코드) 채택**

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|

| **B. 문서 대역 치환** | RFC5737 TEST-NET 으로 형태 유지 | grep·복붙 예시가 문법적으로 계속 유효하다. 자릿수·형태가 보존돼 diff 가 작다 | **가짜 IP 를 진짜처럼 보이게 남긴다** — 다음 사람이 그것을 실주소로 오해할 수 있다. 이 저장소에 선례가 없다 |
| **C. 마스킹** | 마지막 옥텟만 가린다 | 최소 변경. 대역은 남기고 호스트만 가린다 | **대역이 남으면 스캔 비용 절감분이 거의 그대로다.** 반쪽 조치 |
| **★ D. 변수 표기** | `${LLAMA_BASE_URL}` / 환경변수 | 코드·스크립트에는 정확한 표현 | 산문 이력에는 안 맞는다("그날 무엇에 붙었는가"가 사라진다) |

**추천(채택): A(산문·문서) + D(코드·스크립트).** 두 자리는 성질이 다르다 — 산문은 *어느 머신이었나*를 남겨야 하므로 별칭이 맞고, `scripts/*_live_smoke.py` 의 하드코딩 기본값은 애초에 값이 아니라 **환경변수여야 하는 자리**다.

**별칭에 각괄호를 쓴 이유**: CommonMark 의 raw HTML 태그명은 ASCII 문자로 시작해야 하므로 `<베타-LLM>` 은 태그로 해석되지 않고 그대로 렌더된다. 각괄호가 있어야 **자리표시자임이 한눈에** 보인다.

## D3 — 재유입 방지 가드: 얼마나 넓게 무는가 → **D 채택**

가드가 이 슬라이스의 **실제 산출물**이다(파일 수정은 1회성, 가드는 영속). 다만 **테스트 픽스처가 일부러 사설 대역을 쓴다** — 광의 정규식은 정상 코드를 문다.

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **A. 금지 목록(정확 일치)** | 3개 실주소 + 평문 비밀번호 문자열을 **추적 파일 전건**에서 금지 | 오탐 0. 픽스처·CIDR literal 을 건드리지 않는다. 구현이 20줄 | **새 주소의 재유입은 못 막는다** — 다음 머신 주소가 들어오면 가드는 조용하다. 이번 사고의 재발만 막고 같은 종류의 사고는 못 막는다 |
| **B. 광의 RFC1918 + 허용목록** | 사설 대역 전체를 전건 금지하고 픽스처·CIDR literal·감사 기록을 허용목록으로 뺀다 | **종류를 막는다** — 새 주소도 걸린다. 규칙 문언("IP·토폴로지 기록 금지")과 폭이 같다 | 허용목록 유지비가 영구적이다. 정상 작업(새 테스트가 사설 IP 픽스처를 쓴다)이 빨간 불이 되어 **가드를 끄고 싶어지는 압력**이 생긴다 |
| **C. B + 대상 경로 한정** | 광의 정규식을 `docs/` 와 루트 `*.md` 에만 건다(`tests/`·`scripts/` 제외) | 픽스처 마찰이 구조적으로 0(경로로 갈린다). 산문 축은 종류를 막는다 | **`scripts/` 하드코딩이 가드 밖이다** — 이번 사고의 원인 중 하나가 정확히 그 자리다. 경로 예외가 곧 다음 구멍 |
| **★ D. A + C 겹치기** | 정확 일치는 **전건**(`scripts/` 포함), 광의 정규식은 **문서 경로만** | 두 실패 모드를 각각의 자리에서 막는다. 픽스처 마찰 0이면서 `scripts/` 도 덮인다 | 가드가 두 개라 읽는 비용이 조금 는다 |

**추천(채택): D.** 픽스처 마찰(B 의 실질 비용)과 `scripts/` 구멍(C 의 실질 비용)이 서로 다른 축이라 한 규칙으로는 둘 다 못 잡는다. 두 규칙이면 각각 단순해진다.

**시행에서 확정된 것 넷** — 전부 [`test_repo_hygiene.py`](../../tests/test_repo_hygiene.py) 에 잠겨 있다.

- **금지값을 조각으로 조립한다.** 가드 파일에 값을 그대로 적으면 **가드가 자기 자신을 문다** — 그래서 조각으로 나눠 잇고, 그 대가로 **가드 파일도 검사 대상에 남는다**(예외로 빼면 그 자리가 다음 구멍이다).
- **옥텟 4개를 정확히 요구한다.** 3~4개를 허용하면 `npm 10.9.8` 같은 버전 문자열이 잡힌다(실측 4파일).
- **CIDR 표기(`/prefix`)는 통과**시킨다 — 신뢰 대역 계약 literal 이지 호스트가 아니다.
- **`git add` 전의 새 파일도 검사한다.** 추적 파일만 보면 유출이 들어오는 바로 그 순간이 검사 밖이다.

**두 방향 회귀**(CLAUDE.md §4): ① 실주소·비밀값을 되넣으면 실패한다 ② 픽스처가 쓰는 사설 호스트 주소와 계약 CIDR literal 은 **통과해야** 한다 — 과잉 교정으로 그것들을 막으면 Phase S-3 의 XFF 신뢰 셀이 통째로 못 쓰게 되고, 그 방향을 `test_contract_cidr_and_fixture_ranges_are_not_flagged` 가 문다.

## D4 — `scripts/` 3건의 하드코딩 기본값 (코드 변경) → **A 채택**

`phase2a_provider_live_smoke.py` · `phase2b3_compare_judge_live_smoke.py` · `phase4_context_search_planner_live_smoke.py` 가 `DEFAULT_LLAMA_BASE_URL` 로 **동작하는 기본값**을 들고 있었다(감사 §A.17). 문서가 아니라 코드이므로 치환은 곧 동작 변경이다.

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **★ A. 환경변수 필수** | 기본값을 없애고 `LLAMA_BASE_URL` 미설정이면 즉시 실패 | 주소가 코드에서 사라진다. **fail-fast** — 이 저장소가 다른 곳에서 쓰는 패턴과 같다(외부 API 형식 추론 금지 선례) | 인자 없이 돌던 스크립트가 이제 안 돈다(전부 live smoke 라 어차피 환경을 갖춰야 하지만, 절차 문서에 한 줄 추가가 필요) |
| **B. `localhost:9080`** | 기본값을 로컬로 | 무해하고 실행 가능성 유지 | **조용히 틀린 곳에 붙는다** — 로컬에 llama 가 없으면 연결 거부, 있으면 *의도하지 않은 모델*로 측정한다. 이 저장소가 반복해서 경계한 "조용한 품질 저하" |
| **C. 그대로 둔다** | 스크립트는 스윕 대상에서 제외 | 변경 0 | 규칙 위반이 코드에 남는다. D3 의 정확 일치 규칙이 이 파일에서 실패한다(예외를 또 파야 한다) |

**추천(채택): A.** 세 스크립트 모두 외부 LLM 이 있어야만 의미가 있는 live smoke 이고, 기본값이 맞은 적은 구 검증 머신이 현역이던 기간뿐이다 — **지금 그 기본값은 이미 틀렸다.**

**시행**: `default=os.environ.get("LLAMA_BASE_URL")` + `required=not os.environ.get("LLAMA_BASE_URL")`. 환경변수가 있으면 종전대로 선택 인자이고, 없으면 argparse 가 **exit 2 로 즉시 멈춘다**(실측).

## Follow-up considerations

- **가드가 생기면서 `.env.example`·compose 주석이 정확 일치 규칙의 대상에 들어왔다.** 둘 다 깨끗하다(`0.0.0.0`·`127.0.0.1` 은 바인딩 서술이라 사설 호스트 정규식에 안 걸리고, 애초에 광의 규칙은 문서 경로만 본다).
- **감사 기록 예외를 코드 주석에 잠갔다** — *"발견의 근거라 오너 결정으로 보존"* 과 *"★ 이 예외를 지우거나 넓히지 말 것"*. 이유 없는 허용목록 행은 다음 스윕이 지워도 되는지 판단할 수 없다.
- **허용목록이 낡는 것도 가드가 본다**(`test_every_allowlist_entry_still_exists`) — 대상 파일이 사라지거나 이미 깨끗해지면 실패하고 행을 걷게 한다. 예외는 조용히 남는 것이 가장 위험하다.
- **이 브리프는 S-2(nginx 보안 헤더)와 묶이지 않는다.** S-2 는 nginx 를 여는 슬라이스라 레이트리밋·`client_max_body_size` 와 함께 가는 편이 싸다(HANDOFF Next Tasks 0).
