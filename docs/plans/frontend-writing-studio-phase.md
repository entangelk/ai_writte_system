## 목적과 승인 범위

오너는 현재 프론트가 밋밋하고 잘 어울리지 않는다고 평가하고, 눈이 편하면서 작가다운 현대적 느낌을 요청했다. 2026-09-11 후속 요청으로 **추가 페이즈 문서 작성과 구현 진행**을 승인했다. 특정 서체 파일이나 팔레트 교체를 승인한 것으로 확대 해석하지 않는다.

이 문서는 Phase 10을 잇는 **Phase W**다. 다른 트랙의 숫자 페이즈와 혼동하지 않도록 별도 식별자를 쓴다. 슬라이스별 구현 완료와 전체 페이즈의 완료를 구별한다.

## 정본과 기존 결정

- 우선순위: [`../system-contract-sot.md`](../system-contract-sot.md) §문서 우선순위를 따른다. 이 문서는 API·저장 계약을 변경하지 않는다.
- [`10-frontend-design-system-decisions.md`](10-frontend-design-system-decisions.md)의 블루 파스텔·의미론적 토큰·화면별 점진 적용·다크 모드 토큰만 준비 방침을 유지한다.
- 공통 화면 폭 76rem과 헤더/페이지 정렬을 유지한다. 원고 읽기 폭을 다루더라도 페이지 뿌리에 별도 폭을 추가하지 않는다.
- 폼 라벨·접근성 역할·읽기 전용 표시·저장/생성/복구 동작은 유지한다. 보조 패널은 닫혀도 마운트가 유지돼야 한다.
- 옛 문서의 과거 측정값을 현재 사실로 베끼지 않는다. 현재 CSS 가드와 실제 화면을 확인한다.

## 디자인 방향

**시각 방향:** 옅은 블루 바탕 위에 밝은 원고면과 절제된 잉크색을 두는 현대적인 집필 공간. 장식보다 한글 타이포와 여백으로 분위기를 만든다.

**화면 구성:** 작품 선택 → 원고 중심 작업 공간 → 필요할 때 여는 AI/검토/메모. 랜딩 페이지식 대형 이미지·홍보 헤더를 작업 화면에 넣지 않는다.

**상호작용:** 기존 페이지 진입, 도구 드로어 전환, 버튼 hover/focus를 일관되게 유지한다. 원고를 움직이는 장식 모션은 추가하지 않는다. reduced-motion 설정을 존중한다.

| 축 | 구현 기준 | 피할 것 |
|---|---|---|
| 색 | 기존 잉크블루 토큰, 원고는 밝은 독립 면 | 크림/테라코타로 회귀, 토큰 밖 임의 색 |
| 타이포 | UI 고딕과 원고용 한글 서체의 역할 구분 | 영문 서체 이름만으로 한글 외형을 보장했다고 주장 |
| 위계 | 원고가 중심, 보조 정보는 작고 차분하게 | 모든 섹션에 같은 카드·그림자·강한 테두리 |
| 여백 | 반응형 원고 안쪽 여백, 공통 외곽 정렬 | 모바일에서 글 쓸 폭을 과도하게 축소 |

### W1 상세

대상: [`../../frontend/src/styles.css`](../../frontend/src/styles.css).

1. `body`의 반복 세로선 배경을 제거하고 기존 `--surface-page`를 단색으로 사용한다. 검산된 팔레트 값은 바꾸지 않는다.
2. `.editor-form`에 `--surface-card`와 얇은 구분선, 반응형 안쪽 여백을 적용한다. 바깥 페이지 폭이나 드로어 위치를 바꾸지 않는다.
3. 본문 textarea는 폼의 원고면을 공유한다. 기존 1.125rem/1.85 본문 크기·행간과 포커스 하단선, 읽기 전용 색을 유지한다.
4. 세리프 교체·목록 재구성은 후속 슬라이스다. W1을 전체 리디자인 완료로 보고하지 않는다.

### W1a 현재 배치

- 48rem 이하에서는 도구 선택을 원고 앞의 문서 흐름에 둔다. 42rem 이하 2열, 그 위 4열이다. 도구 버튼은 같은 DOM 한 벌이고 완료 배지·드로어 마운트·Escape 포커스 복귀를 유지한다.
- 48rem 초과에서는 기존 고정 우측 띠다. 모바일 도구는 스크롤에 따라 화면 밖으로 이동하며, 위로 돌아가면 다시 접근한다. 스티키로 바꾸면 긴 원고와 겹치므로 다시 경계를 검증해야 한다.
- 320/390/768/1440px 실제 React 앱 검증과 제약은 [`../daily_logs/2026-09-12/work_log.md`](../daily_logs/2026-09-12/work_log.md)를 본다. 다음은 W2다.

### W2 결과 상태(2026-09-12 구현)

- 원고 본문(`.editor-form textarea`)은 `Georgia, "Times New Roman", Batang, AppleMyungjo, "Nanum Myeongjo", "Noto Serif KR", "Noto Serif CJK KR", serif`다 — 한글 음절만 OS별 명조로, 라틴·숫자는 그대로.
- UI(`:root`)는 `Inter, Pretendard, "Noto Sans KR", system-ui, "Malgun Gothic", "Apple SD Gothic Neo", NanumGothic, "Noto Sans CJK KR", sans-serif`다 — 한글 고딕 이름들이 system-ui **뒤**에 있어 라틴 외형이 불변이다.
- 제목 등 나머지 serif 표면(~20곳)은 옛 리터럴 그대로다. 원고 명조가 자리 잡은 뒤 별도 비교로 정한다.
- 한글 폰트가 없는 기기의 두자는 시스템 서체 접근의 한계로 남는다 — 자체 호스팅 웹폰트 갈림길(오너 결정)에서만 해소된다. 실측은 [`../daily_logs/2026-09-12/work_log.md`](../daily_logs/2026-09-12/work_log.md) 세션 64.

### W2 착수 지침(원문 — 완료 슬라이스 기록)

- 기존 스택은 UI `Inter, Pretendard, Noto Sans KR, system-ui`, 제목/원고 `Georgia, Times New Roman, serif`이며 저장소에 웹폰트 로드가 없다(W1 착수 시 확인).
- W1의 로컬 Chromium에서는 제목 한글이 `NanumGothic`, 공백이 `DejaVu Serif`로 렌더링됐다(CDP platform fonts). 이 값은 해당 검증 환경의 관측이다. 다른 사용 환경의 실제 렌더링도 확인한다. OS fallback 추가만으로 모든 기기에서 동일하다고 주장하지 않는다.
- 로컬 시스템 서체 보완은 의존성 없이 검토 가능하다. 웹폰트 도입이 필요하면 파일 출처·라이선스·전송량·자체 호스팅 여부를 비교하고, 소유자 결정이 필요한 의존성 갈림길이면 AGENTS.md의 decision brief를 작성한다.
- 제목까지 무조건 명조로 바꾸지 않는다. 원고 중심의 작은 표면부터 비교한다. 외부 폰트 서비스 호출은 조용히 추가하지 않는다.

| 768×1024 | 약 625.6px | 30.72px | 가로 넘침 없음 |
